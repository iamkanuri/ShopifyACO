# THE ATTACK TEMPLATIZER

**Generate the hostile sentences for a vocabulary review, so the scarce human attention goes to
the part that is not mechanical.**

`VOCABULARY_REVIEW.md` §2 defines the obligatory attack classes. Every defect this project has
found is an instance of one of them. Applying them was a research project with four agents; the
generation half is now a script.

```bash
node --import tsx standards/attack/cli.ts standards/coffee/v1.0/vocabulary/decaf-method.json \
  --context coffee
```

`--seed <s>` · `--limit <n>` (per term per class, default 3) · `--classes a,b` · `--no-controls` ·
`--json`. Exit `0` a run that **completed**, whatever it found · `2` a run that **did not
complete**, so a shell checking only the exit status cannot read INCOMPLETE as clean.

## 1. Eight classes, and where the last two came from

| # | class | source |
|---|---|---|
| 1 | `letter_not_spirit` | `VOCABULARY_REVIEW.md` §2.1 |
| 2 | `adjacent_vocabulary` | §2.2 — **only half mechanisable, see §4** |
| 3 | `wrong_subject` | §2.3, plus `sibling_product`, which §2 under-weights |
| 4 | `merchant_controlled_string` | §2.4, on **nine** surfaces rather than six |
| 5 | `orthography` | §2.5 |
| 6 | `violation` | §2.6 |
| 7 | `tense_modality` | **added by measurement.** The decaf review closed *zero* of `"Until 2024 we used X"`, `"we hope to use X"`, `"we are evaluating X"`, `"we asked about X"`, and none is a subject problem |
| 8 | `denial` | **found by the corpus proof.** §2's class 6 covers the denial shape for *violating* terms only. The mirror — a store denying a **supporting** term — had no class in §2, and it is one of only two classes the decaf review measured as genuinely closed (5/5) |

Class 8 is the more interesting of the two. It did not come from a design review; it came from
taking the sentences four humans actually wrote and asking which of the six each one belonged to.
Two did not belong to any.

## 2. What it produces

Against `decaf-method.json` (39 supporting terms, 0 violating) with the coffee context:

| | at `--limit 3` | uncapped |
|---|---|---|
| attack sentences | 803 | 2,191 |
| controls | 117 | 117 |
| term × class cells | 273 applicable, **0 untested** | same |

Each sentence carries its **class**, its **subclass**, the **term** it targets, the **surface** it
belongs on, and the template's **intent**. Results stratify by class, because the decaf review's
key finding was about *which classes closed*, not how many sentences were written.

**Controls are generated by default.** A set that only attacks measures one direction, and one
direction is exactly how v2.6 shipped: 16/16 denials on its own hostile set, then measured by an
independent pass as a **net regression** — 7 false passes it stopped catching, plus 46 false
fails. `--no-controls` prints that warning before it runs.

## 3. Three properties, and why each is a rule

**Deterministic and seeded.** Same seed → byte-identical set. Different seed → a different
selection with the *same classes and the same counts*, so a re-review after a term change is
comparable rather than unrelated. Selection under the cap is by seeded FNV-1a hash, never list
order: order-based truncation would re-test the same first three templates for ever.

**Category-agnostic.** Nothing coffee-specific is in the generator. Category flavour arrives
through `contexts/{id}.json`, and the test that enforces this is *behavioural* — generate over
neutral terms on the default context and assert no category word appears in any output. (The first
version scanned the source and failed on a comment citing the measured coffee finding, which would
have pushed evidence out of the code to satisfy a check.)

**It scores nothing.** No import from the engine's matcher, asserted by a source scan. Generation
and adjudication stay apart because a generator that judges its own output is the self-attack the
review gate exists to forbid, mechanised and given a version number.

Three things the coverage report refuses to leave silent, each of which was a defect in the first
version and each of which is now pinned by a test:

- **untested cells** — a term with no attack in a class is an *untested term*, reported with a
  named reason, never passed over;
- **classes that ran against nothing** — `decaf-method.json` has an empty violating list by a
  measured decision, so `violation` attacks nothing there. The first run printed `violation 0`
  under a **FULL COVERAGE** headline: a class that never ran, rendered identically to a class that
  ran and found nothing;
- **what the cap dropped** — at `--limit 3` over `decaf-method.json`, **1,388 sentences across 56
  subclasses are not shown**. A cell showing three is not a cell with three available. Found when
  the corpus proof reported a subclass as unreachable that was merely un-picked.

## 4. ⚠️ THE HONEST LIMIT: what it cannot generate

Measured against the known corpus — the sentences four human attackers and one refuter actually
produced, transcribed verbatim into [`corpus/decaf-review.json`](corpus/decaf-review.json).

**It reaches every one of the eight classes.** At subclass level it reaches all but six, and the
six are pinned exactly in `__tests__/attack.test.ts` so that a future change widening the gap fails
a test rather than being discovered by a reviewer who trusted the tool:

```
letter_not_spirit/near_synonym            "Our decaf is 100% chemical free…"
letter_not_spirit/mechanism_without_name  "Green coffee extract is saturated so that only…"
letter_not_spirit/generic_abbreviation    "This is a WP decaf from Huila…"
letter_not_spirit/manner_adverb           "Gently decaffeinated so the origin character…"
letter_not_spirit/quantity_without_name   "We remove 99.9% of the caffeine…"
letter_not_spirit/geography_not_method    "Decaffeinated at origin in Colombia…"
```

**Every one is a case where the hostile string is not the term and cannot be derived from it.**
Knowing that `chemical-free` reads as a near-synonym of `swiss water process`, that `WP` is the
generic abbreviation of three specific ones, or that `99.9%` is a removal rate rather than a
method — that is domain knowledge, and no amount of template engineering produces it.

And this is not a marginal class. It is the class that fills a vocabulary's
`insufficient_evidence`, which `VOCABULARY.md` §2 says must be authored **first**, because for any
claim worth testing the misleading phrasings outnumber the honest ones.

**Class 2 is worse, and the file admits it.** `adjacent_vocabulary`'s domain-collision half is
*replayed* from `contexts/coffee.json`, not derived. The generator "produces"
`"Process: Washed, 1750 masl, Caturra and Castillo."` only because a human put it there. A test
asserts exactly that: with the domains removed, the generator produces **zero** domain collisions.
The context file is a place to *put* human work, not a way to *generate* it.

So the split is clean, and it is the most useful thing this module measures:

> **The generator covers the classes that are a function of the TERM. It cannot cover the classes
> that are a function of the DOMAIN.** Six of the eight classes are term-functions and are now
> mechanical. Two — `letter_not_spirit`'s near-miss half and `adjacent_vocabulary`'s collision
> half — are domain-functions and remain entirely human.

### What it derives that a human had to invent

Two things earn their place, rather than replaying what was already written:

- **`substanceOf` de-frames a framed term.** `VOCABULARY.md` §3.2 requires violating terms to be
  *framed* (`decaffeinated with methylene chloride`, never the bare substance) because an unframed
  term tells a compliant store it stated the opposite. But the violation attack needs the sentence
  a *compliant* store writes, and a compliant store writes the bare substance. Stripping the frame
  by rule reproduces `"Our decaf is free of methylene chloride."` and `"Methylene chloride free
  decaf…"` — hand-written corpus sentences, derived.
- **Fragment probes** emit each term's maximal proper prefix and suffix, which reaches the
  `water process` inside `Sparkling Water Process` shape without anyone having to think of it.

## 5. ⚠️ WHAT MECHANISATION DOES NOT BUY: independence

**A generated attack set is still the author's own set.**

The generator lowers the cost of **coverage**. It does nothing whatever for **independence**, and
independence is the property the review gate is actually built around. `VOCABULARY_REVIEW.md` §1
separates author, attacker and refuter because *"the specific failure mode — a term that sounds
like it names something specific — is invisible from inside that decision"*, and no script changes
who is inside it.

The decaf review is the proof. Its author applied 21 narrowings and verified them by re-running
**the attackers' own sentences** — *"which felt independent and isn't, because those are precisely
the sentences the change was tuned to stop."* An independent refuter then found a **false
statement** in the committed review record: a class reported as closed was 13/13 still failing.
Running a generator would not have caught that. The generator would have produced the same
sentences the author was already re-running.

Concretely, mechanisation moves **one** of the review's steps and leaves the rest:

| step | who |
|---|---|
| write the hostile sentences | **the script**, for six of eight classes |
| supply the adjacent domains | a human, per category |
| write the near-synonym and insufficient phrasings | a human, per category |
| judge whether a generated sentence is *genuinely misleading* | a human |
| decide term-removed vs narrowed vs limit-recorded | a human |
| check the generated copy is copy a merchant would actually write | a human |
| be a **different person from the author** | unchanged, and not machine-checkable |

`VOCABULARY_REVIEW.md` §4 conditions **4** and **6** stay marked as not machine-checkable. A field
claiming otherwise would be doing the thing the whole gate exists to prevent.

## 6. Files

| file | what |
|---|---|
| `types.ts` | the taxonomy, the artifact shapes, and why each class exists |
| `templates.ts` | the sentences. Four phrase builders, all corrected by running them |
| `generate.ts` | generation, seeded selection, coverage, completion state |
| `context.ts` | `CategoryContext`, the generic default, the loader |
| `render.ts` | human and JSON output, organised **by class** |
| `cli.ts` | the command line |
| `contexts/coffee.json` | the coffee context, including nine human-supplied adjacent domains |
| `corpus/decaf-review.json` | the known corpus, verbatim, for the proof in §4 |

Completion state comes from the real `src/measure/completion.ts`, not a copy: `uncoveredCount` is
`number | null` and is **null** on incomplete, never `0`.

Every phrase builder in `templates.ts` was corrected by execution, not by review. Written from the
table, the generator produced `"Ask us about carbon dioxide decaffeination decaf"`, `"We hope to
move this lot to the decaffeinated with methylene chloride"` and `"Our decaf is free of
decaffeinated with methylene chloride"`. An ungrammatical attack sentence is not cosmetic: §2
requires **verbatim store copy** precisely because the one job left to the human is judging whether
a sentence would mislead a real shopper, and nobody can judge that about copy no merchant would
write.
